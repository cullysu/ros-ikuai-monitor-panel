## 2. 可观察的爱快 4.0 设计语言

### 2.1 页面骨架

- 桌面使用窄一级图标栏与领域二级导航，当前入口以浅蓝底和蓝色图标明确标识。
- 主工作区是近白冷灰背景上的低圆角白色面板；细边框和微弱阴影只负责分区，不负责制造“高级感”。
- 系统概览不是一张巨型健康卡，而是设备、WAN、速率、连接、接口、资源、排行等不同任务模块的组合。
- 模块标题短、直接、对象化，例如 `WAN信息`、`线路监控`、`终端流量排行榜`。

### 2.2 信息密度

- 密度来自同行比较：对象名、状态、上行、下行、累计量、占比或阈值尽量处于同一视线。
- 数字稳定右对齐，方向、单位和时间窗紧邻数据，不让用户跨卡片拼接口径。
- 图标只用于领域识别，主要判断仍靠对象名、状态文字和数值列。
- 字号不靠缩到 7–9px 获得密度；紧凑来自行高、列对齐和删除重复解释。

### 2.3 颜色

- 白与冷灰承担大部分表面；蓝色承担选中、可操作、可信当前曲线与关键数据。
- 下载与上传使用稳定的两条系列色，不能在不同模块中交换含义。
- 绿色、橙色、红色只表达已确认的在线、注意和故障；历史、缺失和不可判断使用灰阶及明确文字。
- 不使用大面积酒红事故卡，也不把全部表面染成蓝灰。

### 2.4 对象与操作

- `wan1`、`lan1`、终端、应用、协议等对象名直接出现；“网络良好”“查看详情”不能替代对象。
- 行或面板本身就是入口，点击后直接进入该对象，不经过无信息的中转页。
- 快捷入口存在，但它服务高频任务，不与监控证据争抢视觉中心。
- 异常首先回答“哪个对象、当前什么状态、影响什么”，然后才给解释和下一步。

### 2.5 图表

- 真实图表具有时间轴、纵轴或比例尺、时间窗、对象范围与上下行系列。
- 当前值、峰值和曲线必须使用一致采样窗口；不能让顶部当前值与图内“当前”互相冲突。
- 排行是比较工具：至少包含对象身份、上下行、总量或占比，不是装饰性名次列表。

## 3. 不能照搬到手机的桌面结构

1. 左侧两级导航与悬停展开。
2. 八列以上宽表格。
3. 端口拓扑、完整图表、排行和快捷入口同时并排。
4. 1366px 下的模块顺序直接改成一列。
5. 大量快捷入口九宫格。
6. 依赖鼠标悬停的解释与操作。

手机要继承的是对象、比较、状态和直达效率，不是桌面几何。

## 4. 手机版的明确产品规则

1. 首屏只有一条主线：状态是否可判断 → 当前出口/最高风险对象 → 决定性证据。
2. 正常态由一个 WAN 监控面承担当前上下行、时间窗、出口确认和短趋势，不设大 KPI hero。
3. 每个对象行回答不同问题，禁止 proof、signal、object 三层复读同一组 CPU/WAN/采集字段。
4. 上下行、当前/峰值、在线/总数、当前/阈值必须成对比较。
5. 蓝色只用于可操作与可信当前信息；领域图标底色不得形成彩色卡片田。
6. 事故态先展示受影响对象清单，再展示同域比较和证据边界；布局必须随场景改变。
7. 缺失、历史和不可用不显示为零，也不保留旧速率图。
8. 详情必须新增来源、时间、关联对象、阈值或原始证据，不能放大复读首页。
9. 390px 视觉行高以 40–52px 为主，触控命中区仍不小于 44px。
10. 768px 不是“两张手机卡并排”；应形成对象列表与选中对象证据的稳定工作区。

## 5. 当前生产实现的裁决

当前 `src/panel-framework/mobile-ikuai4/` 已经正确完成：独立手机渲染树、四任务根、对象化 WAN、上下行双序列、事实缺失不伪装为零、事故优先级、真实详情历史和 56 格响应式矩阵。

仍需关闭的 P1：

1. 正常态“对象监控”仍偏领域摘要，缺少更强的同行比较。
2. 图表有起止时间与上限，但纵轴刻度仍不够直接。
3. 接口事故页在故障对象后没有充分利用同链路证据，390px 下半屏空置。
4. 资源压力是三条同构红色进度条，还需要更明确的当前/阈值/连续样本比较。
5. 768px 首页只是左右并排，未形成对象—详情工作区。
6. 当前内容层仍有偏多的圆角白色分组；应保留边界，但进一步减少“通用 iOS 卡片”观感。

## 6. 下一轮实现顺序

1. 先增强对象同行比较与图表刻度，不先调配色和阴影。
2. 再给接口、全离线和采集事故增加同域证据，而不是重复说明。
3. 重构 768px 为对象列表—证据工作区，消除下半屏机械空白。
4. 最后做视觉细化：减少不必要的彩色图标底、统一边框、选中蓝、状态色和按压反馈。
5. 用 7 场景 × 8 视口、200% 文本、强制色、减弱动态和独立原图评审重新签收。

## 7. 学习心得

爱快 4.0 的“专业感”不是蓝色，也不是表格。它来自用户在一次扫视中能把对象、状态、数值、口径和入口对应起来。手机端不能复制爱快的桌面布局，但必须保留这种决策效率。iOS 的作用是让触控、排版、历史、焦点和反馈达到成熟移动产品的完成度；它不能替代爱快的对象语言。
